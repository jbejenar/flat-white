# DEC-008 — Adopt ASGS 2026 as schema 1.0.0

## Status

Accepted for implementation. Data publication is a separate release step.

## Context

The August 2026 administrative archive contains ASGS 2026 census geography.
flat-white's schema 0.x contract and joins used ASGS 2021. Renaming SQL columns
without changing the advertised contract would silently change the meaning of
mesh-block, SA1–SA4 and GCCSA values for downstream consumers.

## Decision

**Schema 1.0.0 change:** use ASGS 2026 throughout the six census fields and record
it as a breaking semantic change. Keep the JSON field shapes, publish the schema
and geography versions in release metadata, S3 manifests and OpenSearch mapping
metadata, and reject incompatible loaded schemas. Do not fall back to 2021 data.

Pin the `202608` loader line with the
[documented authority-cleanup repair](../GNAF-LOADER-UPDATES.md#current-pin-and-upstream-repair).
Retain the February address fixture with a synthetic 2026 census overlay and
2021 regression decoys.

## Alternatives considered

- Keep schema 0.x and pin older 2021 source archives. This would preserve the old
  contract but would not adopt the new upstream geography.
- Mix or silently relabel editions. Rejected because a valid-looking document
  could then produce incorrect geographic joins and reports.

## Consequences

Consumers must check metadata, update geographic references and rebuild affected
indexes and aggregates. Historical comparisons need an explicit edition and,
where appropriate, a suitable ABS correspondence. Older releases remain unchanged.
The first production build needs a fresh compatible database cache.

See the [migration guide](../MIGRATING-TO-ASGS-2026.md) for upgrade and rollback
steps, and the [document schema](../DOCUMENT-SCHEMA.md) for the contract.
